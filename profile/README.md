# Adu Labs

**From requests to tasks. 从请求治理走向任务执行。**

Adu Labs is an evidence-driven engineering lab for production-minded gateways
and reliable agent systems. We build in public through explicit requirements,
architecture decisions, runnable experiments, fault injection, benchmarks, and
post-implementation revisions.

## Planned projects

| Project | Purpose | Status |
| --- | --- | --- |
| `go-gateway-lab` | A clean-room Go API gateway built from first principles | Preparing |
| `agent-execution-lab` | Executable labs for agent loops, tools, state, recovery, tracing, and evaluation | Preparing |
| `task-aware-gateway` | A task-aware AI/Agent gateway for model and tool traffic | Researching |

## How we work

```text
Problem
→ Constraints
→ Decision
→ Alternatives
→ Implementation
→ Verification
→ Revision
```

- Problems come before features.
- Critical behavior is specified and tested before it is trusted.
- Benchmarks include methods, environments, and limitations.
- AI assistance is an implementation tool; contributors remain responsible for
  every decision and every line they submit.
- Public work must be clean-room, reproducible, and free of employer or
  third-party confidential information.
- We expose operational evidence and decision rationale, not private model
  chain-of-thought.

## Current focus

- Go networking, reverse proxies, routing, resilience, and observability
- LLM provider compatibility, streaming correctness, usage, and cost controls
- Agent tools, checkpoints, failure recovery, trajectories, and evaluation
- Task-aware identity, policy, budget, audit, and replay

The lab is currently being bootstrapped. Repositories will become public only
when they contain a runnable vertical slice, verification evidence, and clear
scope boundaries.
